## 诊断：微服务随机挂掉问题

### 诊断结论
经过全量排查（日志分析 + 配置文件审查 + 启动脚本审查），确定服务随机挂掉的**三个根因**：

1. **🔴 OOM Killer（主因）**：`start.ps1` 仅在 prod 模式设置 `-Xms256m -Xmx512m`，standalone 模式下 5 个 Java 进程使用默认 JVM 堆（约 25% × 16GB = 4GB 每个），5 × 4GB + MariaDB + Redis 超过可用内存，操作系统 OOM Killer 随机杀进程。

2. **🔴 无自动重启**：进程退出后 `start.ps1` 直接 `break` 退出；Docker Compose 无 `restart` 策略。

3. **🟡 OTLP 追踪日志轰炸**：所有服务 `tracing.sampling.probability: 1.0`，Jaeger 未启动时每 15 秒报一次 `Connection refused: localhost:4318`，持续消耗线程和 CPU。

### 已实施的修复

| 文件 | 修改内容 |
|------|----------|
| `start.ps1` | standalone/dev 模式添加 `-Xms128m -Xmx256m`；添加 `-XX:+UseG1GC -XX:+ExitOnOutOfMemoryError -XX:+HeapDumpOnOutOfMemoryError`；添加自动重启守护（60秒内最多重启5次） |
| `docker-compose-prod.yml` | 所有服务添加 `restart: unless-stopped`；添加健康检查（actuator/health）；添加 `deploy.resources.limits.memory`；添加 `JAVA_TOOL_OPTIONS` 内存限制 |
| `*/application.yml` (5个) | `tracing.sampling.probability` 从 1.0 改为 0.0（禁用追踪防止日志轰炸）；Redis pool 缩小、添加超时配置；user-service 的 `seata.enabled` 改为 false |
| `*/target/classes/application.yml` | 同步更新 |

### 2026-06-13 补充：502 登录错误

**根因**: `FrontendServer.java` 第 43-46 行硬编码 `sendResponseHeaders(502, -1)` 对所有 `/api/*` 请求直接返回 502。

**修复**: 
- 重写 `FrontendServer.java`：添加 `proxyToGateway()` 方法，使用 `HttpURLConnection` 将 `/api/**` 请求代理转发到 Gateway (`http://localhost:8080`)
- 更新 `start.ps1`：FrontendServer 启动参数增加 gateway URL (`http://localhost:8080`)
- 重新编译 `FrontendServer.java` 到 `target/classes/`

**验证**: 修复后 `curl http://localhost/api/user/login` → 400 "密码错误"（正常业务响应，不再 502）
